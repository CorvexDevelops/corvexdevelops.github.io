    ✓security_of_corvex
    
/* A security tool
should be secure first */

    
Corvex sees code, secrets and open issues. That's why every layer is defended and every change faces more than 300 simulated attacks before release.

  









  

    
01
Only what's yours
Authorisation required and, for public domains, an ownership file. Without it the scan doesn't start.

    
02
Gentle checks
Harmless markers, a request budget and at most 8 requests per second, only on the authorised host.

    
03
Your code stays with you
Corvex runs on your machine or server. Code, files, traffic and results are never uploaded.

    
04
Second factor, always
Password plus a temporary code, or SSO with your provider. Sessions expire after inactivity.

    
05
Encrypted secrets
Tokens, sign-in profiles and integrations encrypted with AES-256-GCM. API keys stored only as hashes.

    
06
Signed updates
Every update is signed with Ed25519, never installed during a scan, always with a backup.

✓layer_by_layer
    
/* Every layer defended */

  

    
+sign_in
Identity and roles

      
  • scrypt passwords, TOTP with reuse blocking
  • SSO OpenID Connect with signature, issuer, audience and nonce checks
  • 256-bit sessions, HttpOnly and SameSite=Strict, lockout after 5 errors
  • reviewer role refused by the server on every action

    
+application
The dashboard passes its own agents' checks

      
  • mandatory anti-CSRF header, Host check against DNS rebinding
  • strict CSP, COOP and CORP, no framing
  • static files from an allow-list, safe archives
  • desktop app with sandbox and context isolation

    
+engagement
Never against someone else's platforms

      
  • anti-SSRF on every request, redirects included
  • private networks and cloud metadata off-limits for users
  • users' code in isolated spaces

    
+ai
An AI that takes no orders from the code it reads

      
  • corvexai only on 127.0.0.1, with a random key
  • MCP server: strict arguments, untrusted data marked, prompt injection flagged
  • fixes only after the user's yes
